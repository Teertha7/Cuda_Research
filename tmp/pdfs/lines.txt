427.1 135.6 I. INTRODUCTION
444.1 59.0 Edge detection shows a useful contract between regular
455.8 49.0 localized computation and multi-stage processing with global
467.8 49.0 connectivity. A Sobel output takes into account a small
479.6 49.0 neighborhood which makes spatial partitioning simple. Canny
491.6 49.0 adds smoothing by using nonmaximum suppression and
503.6 49.0 hysteresis, so distributing individual stages or image regions
515.3 49.0 introduces different correctness measures. Canny originally
527.3 49.0 emphasizes more on detection and localization rather than
539.3 49.0 parallel implementation [1].
551.6 59.0 For a discrete GPU, a short convolution can be completed
563.6 49.0 quickly while host staging, transfers and synchronization
575.3 49.0 dominate application-visible latency. The CUDA based
587.4 49.0 programming model shows parallelism and memory hierarchy
599.4 49.0 [2]; it however does not guarantee that offloading every image
611.1 49.0 will be profitable. Multicore CPU execution is a essential
623.1 49.0 addition for comparison as relying on just sequential baseline
635.1 49.0 is not enough. Benchmark diversity and communication
647.1 49.0 accounting are main concerns in heterogeneous evaluation. [3]
663.9 58.5 We question how image size, CPU thread count, CUDA
675.9 46.0 launch configuration and CPU row fraction change latency
687.6 46.0 under identical Sobel contract. The study uses a reproducible
699.6 46.0 implementation and measurement artifact, a comparison
711.6 46.0 between kernel and pipeline timing, and a held-out
723.6 46.0 diagnostic model of candidate row allocations. It does not
735.4 46.0 claim a new edge detector or a new CPU-GPU dividing
747.4 46.0 principle or an optimized search model. Prior work already

521.8 79.3 IV. SYSTEM DESIGN AND IMPLEMENTATION
541.1 49.0 A. Algorithm contracts
563.9 36.0 All inputs are 8-bit grayscale images. Sobel uses the conventional
574.9 36.0 horizontal mask [−1, 0, 1; −2, 0, 2; −1, 0, 1] and its transpose,
586.0 36.0 with signed integer accumulation and unsigned 16-bit output
596.7 36.0 |Gx| + |Gy|.
620.5 36.0 The outermost output border is set to zero, with no clipping,
632.7 36.0 normalization or thresholding. Integer arithmetic allows exact
645.0 36.0 comparison between CPU and GPU results.
716.4 59.0 The Canny implementation uses a 5×5 smoothing filter
726.4 49.0 formed from the binomial coefficients ([1,4,6,4,1]), normalized
736.4 49.0 by 256. Boundary samples are replicated during smoothing.
746.4 49.0 Sobel gradients are then calculated using floating-point
756.2 49.0 arithmetic to obtain magnitudes and directions. Non-maximum
766.2 49.0 suppression groups directions into four bins, retains ties and
COL 1
46.4 315.1 sets the outer border to zero. Absolute thresholds of 40 and 100
56.4 315.1 are used. Finally, a global serial queue follows eight-connected
66.4 315.1 weak pixels starting from strong pixels. No stage uses OpenCV.
76.2 315.1 This implementation follows a specific Canny variant and does
86.2 315.1 not aim to reproduce every library implementation or the original
96.2 315.1 multiscale detector.

181.3 46.0 The baseline CUDA implementation assigns one thread to
193.8 46.0 each output pixel. The tiled version loads a block and its
206.6 46.0 one-pixel halo into shared memory. All threads reach the
219.3 46.0 synchronization barrier before out-of-range threads return.
231.8 46.0 The tested block configurations are 16 × 16, 32 × 8 and 32 ×
244.6 46.0 16. CUDA calls and launches are checked, and results are
257.3 46.0 read after stream synchronization. Timing distinguishes
269.9 46.0 device execution intervals from host-visible wall time,
282.6 46.0 following CUDA guidance [23].
306.1 55.8 Hybrid Sobel assigns the upper ⌊f H⌋ rows to eight
317.1 46.0 OpenMP threads and the lower rows to CUDA. One
327.6 46.0 preceding halo row is transferred when required, and CPU
338.1 46.0 and GPU outputs occupy separate regions. Pinned host
348.9 46.0 memory supports asynchronous transfer submission

369.9 46.0 the GPU operations are queued, after which the host waits
380.4 46.0 for completion and copies the GPU output into the final
391.1 46.0 array. Fractions 0 and 1 use the same hybrid wrapper.
415.3 55.8 Asynchronous submission alone is not proof of overlap.

171.5 61.0 The primary finding is a difference between where arith-
183.2 51.0 metic runs quickly and where an entire host-to-host image
195.2 53.3 operation runs quickly. For a small regular stencil, device
207.2 51.0 computation is only part of the pipeline. Keeping intermediate
219.0 51.0 data resident on the GPU could change this balance, but it
231.0 59.3 would answer a different question and is not measured here.
243.0 59.3 Adding shared-memory traffic and synchronization can cost
254.7 51.3 more than the reuse it enables. The observed result should
266.8 53.5 inform a future optimization choice, not be hidden by empha-
278.8 51.0 sizing a favorable isolated wall-time sample. Similarly, col-
290.8 50.8 laborative CPU–GPU execution should be compared against
302.5 50.8 both endpoints under repeated controlled conditions. Merely
314.5 51.0 demonstrating correctness and asynchronous submission is
326.5 49.0 insufficient to claim a practical gain.
338.5 59.0 The model is useful as a compact description of this dataset,
350.3 49.0 while the rate-estimate regret demonstrates the limits of ideal-
362.3 49.0 ized divisible-work assumptions. The extensive scheduling lit-
374.3 49.0 erature provides stronger general techniques; our study instead
386.3 49.0 makes the timing scope and the limits of a small empirical
398.0 49.0 model inspectable.
417.3 72.0 VIII. THREATS TO VALIDITY AND LIMITATIONS
432.8 59.0 This is one laptop and one session. The desktop GPU is
444.6 49.0 shared, CPU placement is uncontrolled, and background ac-
456.6 49.0 tivity, thermal state and power policy can affect measurements.
468.6 49.0 Fifteen within-process repetitions characterize local variability
480.6 49.0 without establishing cross-day reproducibility. Table II reports
492.3 49.0 the largest-resolution spread so that small differences are not
504.3 49.0 mistaken for robust improvements.
516.3 59.0 Only synthetic images are measured. Natural-image gener-
528.3 49.0 alization, different machines, energy, GPU-resident pipelines,
540.1 49.0 cold-start latency and production-library baselines remain
552.1 49.0 untested. CPU SIMD tuning is not explicitly optimized.
564.1 49.0 OpenMP Canny retains a serial queue and includes intermedi-
576.1 49.0 ate allocation costs; CUDA and hybrid Canny are not imple-
587.9 49.0 mented. Exact comparison validates the specified algorithms,
599.9 49.0 not perceptual edge quality or agreement with every library.
611.9 49.0 Tests cannot prove absence of all memory errors, and Compute
623.6 49.0 Sanitizer was not run.
635.6 59.0 The model uses a small, structured dataset and configuration
647.6 49.0 medians. MAPE alone does not validate an allocation decision,
659.6 49.0 and no statistically significant or universally optimal partition
671.4 49.0 is claimed. The review verifies source existence and records
683.4 49.0 reading depth, but is not an exhaustive systematic review.
695.4 49.0 Author information and human validation remain required
707.1 49.0 before submission.
